Tokens: turning text into numbers

A neural network can only do arithmetic, so the first step chops the text into tokens and swaps each one for its number in a fixed vocabulary.

The tokenizer is WordPiece with a vocabulary of 30,522 pieces. It lower-cases the text, splits it on spaces and punctuation, and looks each word up. Common words are one token. A rare word is broken into pieces it does know: pieces that continue a word start with ##.

Two special tokens are added. [CLS] ("classification") goes first: by the last layer, its vector will summarise the whole message, and that is what the decision is based on. [SEP] marks the end.

The model reads at most 512 tokens; anything longer is cut off. On this page the limit is 64, so the pictures stay readable.

Show the maths

WordPiece uses greedy longest-match-first: for each word, take the longest prefix that is in the vocabulary, then repeat on the rest (as a ## piece) until the word is used up. If no prefix matches, the word becomes [UNK].

The input is therefore just a list of integers.

Embeddings: a vector for every token

Each token ID is replaced by a list of learned numbers that places it in a space where similar meanings sit close together.

Three lookup tables are added together for every token:

  • Token embedding: what the word is (30,522 rows × 128 numbers).
  • Position embedding: where it sits (512 rows × 128). Attention has no built-in sense of order, so position must be added.
  • Segment embedding: sentence A or B (2 rows). It is always A here.

The sum is normalised with LayerNorm, then a small linear layer projects it from 128 to 256 numbers, the width of the rest of the model. ELECTRA keeps the big vocabulary table narrow (128) to save parameters: at 256 wide it would need 3.9 million more.

Did you know? The token table alone holds 28.8% of all the model's parameters.

Self-attention: tokens looking at each other

The heart of the Transformer. In every layer, each token decides which other tokens matter to it and pulls in information from them.

Every token's vector is turned into three new vectors:

  • Query: what am I looking for?
  • Key: what do I offer?
  • Value: what will I pass on if chosen?

Each query is compared with every key (a dot product). Softmax turns the scores into attention weights that are positive and sum to 1. Each token's new vector is the weighted average of everyone's values.

This happens in 4 heads at once, each with its own 64-number queries, keys and values, so different heads can track different patterns. Their outputs are joined back to 256 numbers and mixed by one more linear layer.

Read with care. Attention shows where information flows, not a full explanation of the decision. Many heads simply park weight on [SEP] or [CLS] when they have nothing useful to do.

Feed-forward, residuals and LayerNorm

Attention mixes information between tokens. The feed-forward network then processes each token on its own.

Each token's 256 numbers are expanded to 1,024, passed through the GELU activation, and squeezed back to 256. The wide middle gives the model room to store patterns; this part holds 46.6% of all parameters.

Around both sub-layers there is a residual connection: the input is added back to the output (x + f(x)). Each layer only has to learn a correction, and gradients can flow straight through all 12 layers during training.

After each addition, LayerNorm rescales every token's vector to a stable range, which keeps training well behaved.

Twelve layers deep

The same block runs 12 times, each with its own weights. Early layers tend to capture surface features such as words and positions; later layers build more abstract meaning.

Only one vector reaches the decision: the [CLS] token after layer 12. Through attention it has gathered information from every other token, layer by layer.

From a vector to a verdict

A small classification head turns the final [CLS] vector into two numbers, then into a probability, then into a yes or no.

The head is two linear layers with GELU in between: 256 → 256 → 2. The two outputs are logits, raw scores for benign and injection. Softmax turns them into probabilities that add up to 1.

Finally the probability of injection is compared with a threshold. We did not use 0.5: the threshold 0.945 was chosen on validation data so that at most 1% of harmless texts get flagged. A higher threshold means fewer false alarms but more missed attacks. Drag the slider to feel that trade-off.

How it learned

Two stages: Google pre-trained ELECTRA on general English, then we fine-tuned it to spot injections.

Stage 1: pre-training (ELECTRA)

BERT-style models learn by hiding 15% of the words and guessing them. ELECTRA does something more efficient called replaced token detection. A small generator swaps some words for plausible fakes, and the main model, the discriminator, must say for every token whether it is original or replaced. Learning from every position, not just 15%, is why a model this small can be this capable. Our guard starts from that discriminator.

Stage 2: fine-tuning (this project)

We added the classification head and trained the whole model on 20,446 labelled texts, checking the loss on 2,433 held-back validation texts four times per epoch. Training stopped once the validation loss had not improved for three checks in a row, and the best checkpoint (epoch 1.5) was kept. After that point the model starts memorising its training data: training loss keeps falling while validation loss rises.

From a training notebook to your browser

The trained model was exported and compressed so it can run on this page without any server.

ONNX is a portable format that describes the model as a graph of maths operations. Your browser runs that graph with ONNX Runtime Web (compiled to WebAssembly), loaded through transformers.js.

Quantization stores each weight matrix as 8-bit integers plus one scale factor, instead of 32-bit decimals. The file shrinks from 54.4 MB to 14.1 MB, and it gives the same verdict as the full-precision model on 3,369 of 3,383 test texts (99.6%).
